# NetVentoy

> **Ventoy for the Network Age** — Self-hosted PXE network boot server with web UI.
> Debian 13 (Trixie) native — zero pip dependencies.

---

## Architecture

```
PXE client powers on
  ↓  DHCP broadcast
Router assigns IP ← NetVentoy dnsmasq (ProxyDHCP, port 67) adds PXE info
  ↓
EFI client: shimx64.efi (TFTP) → grubx64.efi (Secure Boot signed) → grub.cfg
BIOS client: grub/i386-pc/core.0 (TFTP) → grub.cfg
HTTP Boot:   shimx64.efi (HTTP) → grubx64.efi → grub.cfg
  ↓
grub.cfg generated by NetVentoy — boot menu appears
  ↓
User selects ISO → boots via HTTP (kernel+initrd, loopback, or wimboot)
```

### Boot Methods (per ISO, in priority order)

| Method | When used | Secure Boot |
|---|---|---|
| **Direct kernel+initrd** | Kernel extracted via web UI | Compatible (distro-signed kernels) |
| **Grub loopback ISO** | Default (no extraction needed) | Depends on ISO contents |
| **WinPE via wimboot** | Windows ISOs after WinPE extraction | Requires SB disabled or key enrolled |

## Dependencies — APT Only

```bash
sudo apt install python3-flask python3-werkzeug python3-watchdog dnsmasq xorriso wget
```

No `pip`, no virtual environment, no external package index.

| APT Package | Purpose |
|---|---|
| `python3-flask` | Web UI & REST API |
| `python3-werkzeug` | WSGI utilities, secure file upload |
| `python3-watchdog` | inotify-based filesystem watching |
| `dnsmasq` | ProxyDHCP + TFTP server |
| `xorriso` | ISO kernel/WinPE file extraction |
| `shim-signed` | shimx64.efi — Microsoft-trusted EFI shim |
| `grub-efi-amd64-signed` | grubnetx64.efi — distro-signed netboot grub (EFI) |
| `grub-efi-amd64-bin` | Grub EFI modules |
| `grub-pc-bin` | grub-mknetdir — generates BIOS PXE core image |
| `wget` | Downloads wimboot binary during WinPE extraction |

## Quick Start

```bash
# 1. Install
sudo apt install python3-flask python3-werkzeug python3-watchdog \
    dnsmasq xorriso shim-signed grub-efi-amd64-signed grub-pc-bin wget

# 2. Set up boot chain
sudo bash setup.sh

# 3. Run
sudo python3 app.py
```

Open **http://YOUR-IP:5000**

| Feature | Detail |
|---|---|
| **Secure Boot support** | MS-signed shim → distro-signed grub chain for EFI clients |
| **BIOS + EFI + HTTP Boot** | Full grub boot chain for all client firmware types |
| **Directory menus** | Sub-folders in `isos/` become grub submenus |

## Router / DHCP Configuration

NetVentoy uses **ProxyDHCP** — it responds to PXE clients on your subnet without
assigning IP addresses. Your existing router/DHCP server continues to handle IP
assignment. In most setups, **no router changes are needed**.

> **Important:** Remove any existing PXE/next-server/boot-filename options from
> your router. dnsmasq ProxyDHCP is the sole PXE authority.

If your router does not support ProxyDHCP passthrough, you can set:

| Setting | Value |
|---|---|
| Next Server (`siaddr`) | `YOUR-SERVER-IP` |
| Boot filename (EFI) | `shimx64.efi` |
| Boot filename (BIOS) | `grub/i386-pc/core.0` |

### OpenWrt / DD-WRT (dnsmasq on router)

If your router runs dnsmasq, ensure it does **not** set PXE options — NetVentoy's
own dnsmasq instance handles that via ProxyDHCP.

## Kernel Extraction

For best performance, extract kernel+initrd from ISOs using the **Extract Kernel**
button in the web UI. This enables direct HTTP boot (fastest method) instead of
grub loopback.

The web UI auto-detects kernel paths for Ubuntu, Debian, Fedora, Arch, Alpine,
openSUSE, Gentoo, and more. Extraction requires `xorriso` (`apt install xorriso`).

---

## Windows PE

Windows ISOs are booted via [wimboot](https://ipxe.org/wimboot). The process is
automated through the web UI:

1. Upload a Windows PE ISO
2. Click **Extract WinPE** — extracts boot files and downloads the wimboot binary
3. The grub menu entry is generated automatically

> **Note:** wimboot is not Microsoft-signed. Secure Boot must be disabled or a
> custom key enrolled for Windows PE network boot.

## Diagnostic Tool

A standalone PXE/DHCP validation tool is included at `tools/pxe_validator.py`:

```bash
# Test DHCP handshake
sudo python3 tools/pxe_validator.py --interface eth0

# Full test including TFTP connectivity
sudo python3 tools/pxe_validator.py --interface eth0 --test-tftp

# Debug mode (prints every frame)
sudo python3 tools/pxe_validator.py --interface eth0 --debug
```

Uses AF_PACKET raw sockets so it works alongside NetworkManager.

## Troubleshooting

**Client doesn't get PXE boot option**
- Check UDP 67 isn't blocked: `sudo ss -ulnp | grep :67`
- Verify dnsmasq is running: check the status indicator in the web UI header
- Ensure your router has no conflicting PXE/next-server options set
- Run the diagnostic tool: `sudo python3 tools/pxe_validator.py --interface <iface>`

**Menu appears but ISO won't boot**
- Check kernel args in the web UI match the distro
- View the grub menu preview in the web UI to inspect the generated config
- Try extracting kernel+initrd for the ISO (avoids loopback compatibility issues)

**EFI client fails with Secure Boot**
- Verify shimx64.efi and grubx64.efi are in the `tftp/` directory
- Run `sudo bash setup.sh` to restage the boot chain
- Check the web UI status panel for missing boot chain files

**dnsmasq won't start**
- Must run as root: `sudo python3 app.py`
- Kill any existing dnsmasq: `sudo systemctl stop dnsmasq`
- Check port conflicts: `sudo ss -ulnp | grep :67`
